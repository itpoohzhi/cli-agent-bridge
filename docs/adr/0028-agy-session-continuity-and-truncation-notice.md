# ADR-0028: Continuity горячих сессий agy без chat-id клиента и уведомление модели об усечении

- Статус: Proposed (run `20261119-repeat-loop-fix`, Architecture Packet AD-001..AD-005)
- Дата: 2026-11-19
- Связанные: ADR-0008 (head-pruning, персистентность сессий), ADR-0019 (якоря истории)

## Контекст и проблема

DeepSeek Harness 0.2.2-rc.1+ перестал передавать `x-dsh-chat-id`/`x-session-id`/`extra_body.cwd`.
Фасад `:9882` их не теряет (заголовки и тело прозрачны), поэтому agy-bridge `:9887` получает пустой
ключ сессии и каждый ход идёт `sess=plain resume=0`: вся история пересобирается в одну строку NDJSON
под потолок 98 304 Б, ~61 КБ из которого занимает защищённое системное сообщение. Tool-результаты
активного шага молча усекаются, модель перечитывает те же файлы — цикл (586 вызовов, 453 повторных).

## Драйверы

- Агент-агностичность: решение в ядре, без ветвлений по имени клиента и без правки вендора.
- Нулевая склейка контекста разных чатов.
- Конфигурируемость и kill-switch без рестарта; дефолт = прежнее поведение.
- M-MOD/v1: baseline-монолит `bridges/agy-bridge/server.py` не растёт (delta <= 0, фасады <= 5 строк).

## Решение

1. `core/session_continuity.py::ContinuityIndex` выводит устойчивый chain-id чата из содержимого:
   сигнатура `resolve(messages, scope='') -> chain`, где `scope` кодирует только `model`
   (`f"{model}\x00"`); `cwd` в scope не входит. Ключ поиска — sha256 от
   `(scope, канонизированный messages[:last_assistant])`, регистрация — sha256 от
   `(scope, полный messages)` (синхронно до запуска `agy`). Ссылка одноразовая (pop): идентичные
   истории разных чатов дают tombstone (оба хода холодные), а не склейку.
   **Криптографический якорь.** Ссылка ищется и регистрируется только для среза истории, в котором
   есть сообщение `assistant` с непустым `tool_calls[].id` (id выдаёт мост, 96 бит, угадать нельзя).
   Ход 1 (`[system, user]`) ничего не ищет и не регистрирует — холодный chain. Ход 2 холодный
   (префикс без якоря), но регистрирует полный дайджест с уникальным `tool_call_id`. Ход 3..N —
   горячие `resume=1`: префикс содержит id предыдущего хода. Чаты с идентичным `[system, user]`
   не склеиваются даже при интерливинге `C1→C2→A1→C2_retry→A2` и после рестарта моста или
   вытеснения по TTL/LRU (после них ход просто холодный).
   Chain используется только при отсутствии и явного chat-id, и непустого `cwd` (пустая или
   пробельная строка `cwd` считается отсутствующим, как в `_normalize_cwd`), при `tools > 0` и
   флаге `session_continuity_enabled` (дефолт false).
2. `core/prompt_truncation_notice.py` добавляет в промпт уведомление модели, если усечён хотя бы
   один активный tool-результат (флаг `truncation_notice_enabled`, дефолт false). Промпт с
   уведомлением (дефолтный шаблон <=300 Б) не превышает лимит 98 304 Б (например, система 61 КБ +
   уведомление ~0.3 КБ оставляют ~37 КБ под усечённый tool-результат); только если защищённые якоря
   сами занимают >= (limit - notice_len), возвращается промпт без уведомления.
3. Потолок 98 304 Б не меняется (agy режет хвост длинного входа; безопасный запас не подтверждён).
4. `_session_key_for` переносится в `core/session_continuity.py`; в мосту — делегирующая обёртка.

## Отвергнутые альтернативы

- Ключ по cwd или статический заголовок в профиле DSH — склеивает параллельные чаты.
- Отказ (4xx) вместо усечения — рвёт агентный цикл.
- Сжатие системного сообщения — теряет гейты канона.
- Подъём потолка до 128 КиБ без замера `agy.real` — риск молчаливой потери хвоста (текущего ввода).

## Последствия

- Горячие сессии восстанавливаются для любых клиентов без chat-id; при переписывании истории клиентом
  (компакция) — один холодный ход и новая цепочка.
- Ссылки continuity только в памяти, ограничены `AGY_BRIDGE_CONTINUITY_MAX_LINKS` и TTL простоя сессии.
- Откат: флаги false в `dynamic_config.json` моста (без рестарта).
