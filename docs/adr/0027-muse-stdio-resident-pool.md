# ADR-0027: Перевод провайдера Meta Muse в универсальный резидентный stdio-пул

- **Статус:** Accepted
- **Дата:** 2026-11-18
- **Решение Совета:** `arch-v16 ACCEPT`

## Контекст

Провайдер `muse` использовал собственный тип `kind: muse` (`streaming_mode: serve`
на `proxy_port: 10816`), отделённый от универсального резидентного пула
`core/stdio_resident/`, принятого в [ADR-0025](0025-universal-stdio-resident-pool.md).
Поддержание отдельного жизненного цикла усложняло управление слотами, отмену
запросов и гарантированную уборку дочерних процессов.

При переводе `muse` на `kind: stdio_resident` требовалось одновременно:

1. Не модифицировать защищённые монолиты `server.py` и `core/backend_adapter.py`.
2. Обеспечить строгую fail-closed изоляцию пользовательских сессий и сохранить
   prompt caching в рамках закреплённого резидентного процесса.
3. Сохранить обязательную проверку целостности бинарника (`pin_required: true`)
   без расширения схемы `fingerprint` в `core/provider_manifest.py`.
4. Выдержать строгую модульность новых/изменяемых компонентов (≤ 300 строк на модуль).

## Решения владельца

1. **Проверка `verify_binary` SHA-256 (Вариант А):** контроль целостности
   исполняемого файла/лаунчера (`~/.local/bin/muse`) опирается на эталонный
   `binary_sha256` и `version: "1.4.23"` в секции `fingerprint` манифеста
   `providers.d/muse.yaml` без добавления лишних полей, нарушающих схему
   `_parse_fingerprint` в `core/provider_manifest.py`.
2. **Fail-closed изоляция и сохранение prompt caching:** маршрутизация и аренда
   резидентных слотов работают в режиме fail-closed без подстановки общих
   идентификаторов `"default"` или `"anon"`. При отсутствии валидного ключа
   сессии запрос отклоняется, а при наличии стабильного ключа закреплённый
   процесс переиспользуется только для этой сессии, сохраняя prompt caching.

## Архитектура (Вариант А)

Принят **Вариант А** интеграции через существующий контракт универсального
резидентного пула без правок в защищённых монолитах `server.py` и
`core/backend_adapter.py`:

1. **Манифест `providers.d/muse.yaml`:** переводится с `kind: muse` на
   `kind: stdio_resident` с транспортом `wrapper: ~/.config/muse-launch/muse-cli.sh`,
   `proxy_port: 10816`, `options: {protocol: msp-v1}` и обновлённым `fingerprint`
   (`binary_path`, `binary_sha256`, `version: "1.4.23"`). Модели, `family_rule`,
   `models_overrides`, `limits` и `params` сохраняются без регрессий.
2. **Прокси-адаптер `MuseMspDriver` (`"msp-v1"`):** реализует протокольный
   драйвер `"msp-v1"` для взаимодействия универсального пула с прокси/CLI Muse,
   изолируя вендорскую специфику протокола от ядра пула.
3. **Уборка процессов `process_reaper.py`:** обеспечивает контроль и
   детерминированное завершение дочерних/осиротевших процессов при таймаутах,
   отмене ходов, сбоях и завершении работы сервиса.
4. **Модульность ≤ 300 строк:** код драйвера, вспомогательной логики и тестов
   декомпозируется на небольшие одноцелевые модули объёмом не более 300 строк.

## Компоненты и тесты

| Компонент | Роль в архитектуре |
|---|---|
| `providers.d/muse.yaml` | Манифест провайдера `kind: stdio_resident` (`protocol: msp-v1`, pin SHA-256 и `"1.4.23"`, модели и лимиты) |
| `core/provider_manifest.py` | Парсинг и валидация манифеста (`_parse_fingerprint`) без лишних полей в `fingerprint` |
| `MuseMspDriver` (`"msp-v1"`) | Прокси-адаптер / протокольный драйвер `"msp-v1"` поверх универсального пула |
| `process_reaper.py` | Гарантированное завершение и очистка дочерних процессов |
| `server.py`, `core/backend_adapter.py` | Защищённые монолиты — остаются без изменений (Вариант А) |
| `tests/test_stdio_resident_muse.py` | Тесты протокола `"msp-v1"`, `verify_binary` SHA-256, fail-closed изоляции без `"default"`/`"anon"`, prompt caching и reaper-логики |

## Последствия

- Провайдер `muse` переходит на единый резидентный stdio-пул ([ADR-0025](0025-universal-stdio-resident-pool.md))
  без дублирования управления процессами и без риска затронуть `server.py` и `core/backend_adapter.py`.
- Исключается риск утечки контекста через fallback-ключи `"default"` и `"anon"`
  при одновременном сохранении prompt caching для валидных изолированных сессий.
- Проверка `verify_binary` SHA-256 гарантирует запуск только верифицированного
  бинарника при полном соответствии схеме `core/provider_manifest.py`.
- Ограничение размера модулей (≤ 300 строк) и выделение `MuseMspDriver` и
  `process_reaper.py` упрощают сопровождение и верификацию через `tests/test_stdio_resident_muse.py`.
