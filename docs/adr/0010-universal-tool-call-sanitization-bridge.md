# ADR 0010: Универсальная нормализация и санитизация аргументов tool_calls на уровне cli-agent-bridge

## Статус
Proposed — передано на рассмотрение Архитектурной панели / Совета Тимлидов.

## Контекст и проблема
1. **Симптом сбоя:**
   При работе клиентов и оркестраторов (включая DeepSeek Harness, Cursor, скрипты автоматизации) с моделями через мосты, модели (в частности, `gpt-6.1-terra` через OpenAI/Codex API) заполняют опциональные параметры инструментов пустыми строками вместо их опускания:
   - `subagent`: `{"cwd": "...", "description": "...", "prompt": "...", "provider": "", "model": "", "reasoning_effort": ""}`
   - `bash`: `{"command": "...", "sandbox_permissions": "workspace-write", "justification": ""}`
   - `list_subagent_models`: `{"provider": "", "model": ""}`
   Клиентское ПО со строгой валидацией отклоняет такие вызовы:
   - `Error: child LLM \`provider\` must be non-empty`
   - `Error: invalid justification: expected a non-empty sentence`
   - Дополнительно модель пытается обойти ошибку, вызывая несуществующий синтетический инструмент `parallel {"tool_uses": [...]}` (`Error: unknown tool "parallel"`).

2. **Жёсткий архитектурный инвариант (требование владельца в `AGENTS.md`):**
   - **Запрет на правку вендорского ПО:** мы не можем и не будем модифицировать код клиентских приложений (DSH, Cursor, Claude Code и др.) ни в виде бинарных патчей, ни через оверлеи в профилях (`~/.dsh`, `~/.claude`).
   - **Принцип универсальности:** все доработки реализуются исключительно в нашем собственном коде (`cli-agent-bridge`), на универсальном уровне фасада и ядра эмуляции инструментов, защищая любые подключённые клиенты от дефектов генерации любых моделей.

## Архитектурные решения

### AD-001. Универсальный пайплайн санитизации tool_calls в `core/tool_emulation.py`
В модуле [core/tool_emulation.py](file:///Users/aazhiry1/work/src/cli-agent-bridge/core/tool_emulation.py) реализуется чистая функция `sanitize_tool_call(tool_call: ToolCall, tool_schemas: dict[str, Any] | None = None) -> list[ToolCall]`:
1. **Очистка пустых строк:**
   Аргументы инструмента парсятся из JSON-строки в словарь. Для каждого строкового поля:
   - если `isinstance(v, str) and v.strip() == ""`:
     - если известна схема инструмента и поле НЕ входит в список `required` — ключ удаляется из словаря;
     - если схемы нет, но поле имеет типичный опциональный маркер (`provider`, `model`, `reasoning_effort`, `justification`, `cwd`) — ключ удаляется из словаря;
     - для поля `justification`, если передан `sandbox_permissions`, вместо пустой строки подставляется безопасный дефолт (`"Выполнение запрошенной операции"`), предотвращая отказ валидатора песочницы.
   - очищенный словарь сериализуется обратно в компактный JSON без лишних пробелов.
2. **Распаковка синтетического инструмента `parallel`:**
   Если `tool_call.function.name == "parallel"`:
   - из аргументов извлекается список вложенных вызовов (`tool_uses` или `calls`);
   - каждый вложенный вызов преобразуется в самостоятельный валидный `ToolCall` первого уровня (с рекурсивной санитизацией его аргументов);
   - функция возвращает список распакованных `ToolCall` вместо одного вызова `parallel`.
3. **Идемпотентность и безопасность:**
   Если аргументы не являются валидным JSON (например, модель ещё стримит или сгенерировала текст), они не повреждаются и возвращаются как есть (fail-safe).

### AD-002. Интеграция в фасад `server.py` (Non-streaming & SSE Streaming)
1. **В нестриминговом режиме (`stream: false`):**
   В методе формирования `ChatCompletionResponse` перед отдачей клиенту массив `message.tool_calls` пропускается через пайплайн санитизации:
   ```python
   sanitized_tool_calls = []
   for tc in raw_tool_calls:
       sanitized_tool_calls.extend(sanitize_tool_call(tc, tool_schemas))
   ```
2. **В потоковом режиме (`stream: true`):**
   При потоковой сборке вызовов инструментов в SSE (`delta.tool_calls`):
   - аргументы накапливаются в сессионном буфере хода;
   - финальный чанк с `arguments` (или чанк перед `finish_reason: "tool_calls"`) нормализуется, гарантируя, что клиент получает валидный JSON без пустых опциональных ключей.

### AD-003. Обогащение схем инструментов на входе (Prompt-level Defensiveness)
При рендеринге tool schemas в системный промпт (модели text-only или эмулируемые бэкенды) в описание опциональных полей добавляется явная директива:
`"Omit this parameter completely if using defaults; DO NOT pass empty string \"\""`.
Это уменьшает частоту генерации пустых полей на стороне LLM ещё до работы санитизатора.

## Последствия и преимущества
- **Полная изоляция от вендоров:** клиенты (DSH и др.) получают чистый, валидный OpenAI-совместимый ответ без пустых строк, не требуя ни единой строчки правок в коде самих клиентов.
- **Поддержка любых моделей:** устраняется специфика `gpt-6.1-terra` и других строгих schema-following моделей.
- **Автоматическое устранение сбоев:** исчезают ошибки `child LLM 'provider' must be non-empty`, `invalid justification`, `unknown tool "parallel"`.
- **Тестируемость:** логика покрывается 100% модульными тестами в `tests/test_tool_emulation.py` и сквозными тестами в `tests/test_bridge_strict.py`.
