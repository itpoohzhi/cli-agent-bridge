# Сквозной `req_id` в цепи `:9882 -> :9887 -> agy-cli.sh -> :10830`

## Что реализовано

| Узел | Валидация/генерация | Что делает |
|---|---|---|
| Хаб `:9882` (`server.py`) | allowlist `[A-Za-z0-9_.-]{1,64}`, при отсутствии/невалидности — `req_`+uuid12 | резолвит `X-Request-Id` (header → `extra_body` → body), добавляет проверенные заголовки в ответ и в запрос к бэкенду (`passthrough_facade`) |
| agy-bridge `:9887` (`bridges/agy-bridge/server.py`) | `fullmatch` по `[A-Za-z0-9_.-]{1,64}`, иначе `req_`+`secrets.token_hex(8)` | пишет `req_id=` в строку `done`, выставляет `AGY_REQUEST_ID` в окружение потомка (перекрывая унаследованное), сырое невалидное не логируется |
| `agy-cli.sh` | allowlist `^[A-Za-z0-9_.-]{1,64}$` | санитизирует `AGY_REQUEST_ID`: валидное экспортирует, невалидное снимает (`unset`), fail-open |
| `:10830` (`model-georouter`) | allowlist `^[A-Za-z0-9_.-]{1,64}$`, иначе `req_`+`secrets.token_hex(8)` | пишет `req_id=` и `ttft_ms=` в строку `request` |

## Осознанное ограничение (последний хоп)

`agy.real` — закрытый бинар. Он не принимает correlation ID и не добавляет
`X-Request-Id` в собственный HTTP-трафик к `CLOUD_CODE_URL` (`:10830/cloudcode`).
Следствие: запросы agy.real приходят на `:10830` без заголовка, и гео-роутер
генерирует собственный `req_<16hex>`. Гарантия «на маршрутизируемых вызовах нет
`req_id=-`» выполняется, но **единый** ID между `:9887` и `:10830` для этого
типа трафика не достигается и не заявляется.

## Метрики `done` (`:9887`)

`queue_wait_ms` (ожидание слота), `spawn_ms` (Popen), `first_event_ms` (первое
валидное событие stdout), `ttft_reasoning_ms` (первое reasoning-событие),
`ttfc_ms` (первый контент), `gen_ms` = `wall_ms - ttfc_ms`, `stream_chunks`.
Недоступное значение — `-`.
