**Критерий 2 — NEEDS_WORK (`contracts_and_invariants`).** Есть два существенных противоречия.

- В §2.6 цель 320k названа мягкой: обязательный набор размером, например, 350k допускается под жёсткой границей 400k. Однако §2.5 требует сокращать хвост, пока собранный промпт превышает `target`, а T-04 требует результат ≤320k. После удаления всего необязательного хвоста выполнить это невозможно. Нужно явно определить успешный исход для диапазона `target < mandatory ≤ limit`, включая окончательную проверку собранного промпта, маркеры и overhead. Отказ и дальнейшее удаление обязательных сообщений здесь противоречат §2.6.
- В §2.4 принадлежность результатов инструментов определяется совпадением ID со всей историей. При повторном использовании одного `tool_call_id` двумя assistant-ходами группы могут пересечься, а старый результат попасть к новому вызову. Нужна однозначная привязка к конкретному родительскому сообщению с сохранением порядка либо явная политика отказа для неоднозначного входа. Совпадение строкового ID само по себе недостаточно.
