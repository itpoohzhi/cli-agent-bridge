Общая оценка: идея реалистична и минимальна по диффу, примерно 40 строк плюс тесты. Но в r2 сохранились неточности, которые при реализации дадут падения или холостые правки. Все они исправимы без смены архитектуры.

### F-001 BLOCKER-OPINION — `_parse_runtime_flags` в текущем виде упадёт на строковом поле
Доказательство: `bridges/agy-bridge/server.py:2953-2968`. Цикл идёт по всем `_RuntimeFlags._fields`. Там `values: dict[str, bool]` и безусловная проверка `isinstance(value, bool)`.
- Пакет (§3.1 п.2) описывает только «проверять строковый тип», но не говорит, как поле выделяется из цикла.
- Если добавить `str`-поле без специальной ветки, любой валидный конфиг будет отвергаться целиком с `ValueError`.
- Выбор поля в цикле тоже не описан: `default = getattr(_COLD_FLAGS, name)` вернёт строку.
Нужно явно описать отдельную ветку для строкового поля (или вынести его из `_RuntimeFlags`), поправить аннотацию `dict[str, object]` и добавить тест на разбор.

### F-002 BLOCKER-OPINION — невалидная строка в `dynamic_config.json` отвергает файл целиком
Доказательство: `server.py:2965-2966` и обработка `ValueError` в `_runtime_snapshot` (около `server.py:2995`, действует last-known-good).
- Если для `graceful_timeout_finish_reason` сохранить текущую политику (не `str` → `ValueError`), то опечатка вроде `"lenght"` или `null` отключит все остальные флаги.
- Под отключение попадёт, например, `graceful_timeout_on_partial`. Это тихая деградация по одному некритичному полю.
- Реалистичнее принимать любую строку, а нормализацию (`length`/`max_tokens` → `length`, иначе `stop`) делать в `_graceful_finish_reason()`.
- Для не-строки (например `null`) оставить дефолт `stop`, без отказа от файла.
- Это согласуется с самим пакетом: в §3.1 «нераспознанное значение» env тоже просто падает на следующий уровень.

### F-003 NON_BLOCKING — определение `_RuntimeFlags` в пакете устарело
Доказательство: `server.py:2924-2931`. В классе есть шестое поле `stream_resilience_enabled: bool = True`, которого нет в пакете.
- Для него в `_parse_runtime_flags` уже есть особая ветка: `raw.get(_NEW_FLAG_ENV[name], default)`.
- Для нового поля `_NEW_FLAG_ENV[name]` вызывать нельзя, будет `KeyError`. Это связано с F-001.
- Нужно сверить пакет с текущим кодом и добавить поле в конец.
- Также не допустить, чтобы `_new_flag()` (`server.py:3019`) вызывалось с именем строкового поля.

### F-006 NON_BLOCKING — смена дефолта на `stop` ухудшает диагностику усечённого ответа
Доказательство: §2 AD-3.
- Для любого клиента, кроме DSH, `stop` маскирует то, что ответ оборван по времени. Автоматика агентов перестаёт отличать полный ответ от усечённого.
- Это разумный компромисс ради устранения ложного баннера, но он меняет внешний контракт.
- Нужно явно зафиксировать это в ADR (следующий номер после 0021) и в notice в тексте ответа. Префикс `[⚠️ Превышен лимит времени…]` остаётся единственным сигналом, поэтому его нельзя ослаблять.
- Эксплуатационно: рекомендуется заодно залогировать выбранный `finish_reason` в момент graceful-завершения.
- Проектное правило про фичефлаги GigaRC выполняется, так как есть ключ в `dynamic_config.json`. Но дефолт `stop` меняет поведение «по умолчанию». Это стоит оговорить явно, потому что правило требует дефолт, сохраняющий прежнее поведение.
