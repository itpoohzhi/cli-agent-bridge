1.1 Сид. seed_input = «<artifact_sha8>#<run_slug>#c<N>#R<M>» — LC_ALL=C, без пробелов, БЕЗ завершающего перевода строки (перевод строки меняет хеш); artifact_sha8: текстовое решение — SHA-256 файла решения; code-раунд teamlead-gate — SHA-256 коммита/ревизии под ревью (байтовый вид diff нестабилен); run_slug = слаг run-каталога; вне run-dir строка сида — в статус цели verbatim. SEED = первые 8 hex SHA-256(seed_input) (пример: printf '%s' "$SEED_INPUT" | shasum -a 256 | cut -c1-8). Журнал rounds.tsv (run, c, R, seed_input, seed_hex, состав, hats, status) —
    append-only, производный от манифестов раундов; номера c/R монотонны; переигровка без записи = нарушение. seed_input — в манифест байт-в-байт; расхождение строки = блокер раунда.
1.2 Жеребьёвка — хеш-ранжирование по всему пулу сетапа (без якоря). Новый жребий на КАЖДОМ раунде (R1, R2/D-раунды, forced-dissent, раунд согласования C1; директивы 08.10 и 13.10.2026; forced-dissent и C1 — всегда полная коллегия из 3 судей, не один судья и не «только несогласные»), свой seed_input с номером раунда: во всех пакетах (`default`/`fast`/`quality`) все 3 модели из пула сетапа и их рабочие транспорты выбираются заново, роли (Скептик/Реалист/Визионер) перемешиваются заново; состав раунда не наследуется и не складывается с составами других раундов — в каждом раунде свои ровно 3:
    - rank(slot) = SHA-256(SEED + '#' + slot_id); порядок — возрастание hex (LC_ALL=C); тай-брейк равных hex — лексикографически по slot_id. Пересчитывается любым shasum/sha256sum.
    - Закреплённого «якорного» сиденья нет ни в одном пакете (`default`/`fast`/`quality`, директива 13.10.2026): все слоты пула равноправны и ранжируются единым списком `ranked_order[]`; на сиденья 1–3 берутся первые по рангу рабочие слоты разных семейств из пула сетапа.
    - Группы пула: native (семья имеет host-native транспорт текущего хоста) и external (только внешние транспорты, model-invocation.md).
    - Заполнение сидений 1–3: по порядку `ranked_order[]` из рабочих моделей пула разных семейств (при |native|≥2 сиденья 1–2 — первые по рангу рабочие из native, сиденье 3 — первая по рангу незанятая рабочая семья из всего пула; при |native|<2 все 3 сиденья набираются по общему порядку `ranked_order[]` из рабочих моделей пула до 3 судей). Недоступный судья заменяется рабочими транспортами своего слота, затем следующим по рангу рабочим кандидатом пула, затем независимым сабпроцессом рабочей модели/транспорта (1.4, 1.8); упавший не голосует.
    - Anti-repeat: окно 2 раунда (состав сверяется с R−1 и R−2 по манифестам прошлых раундов), сквозное по прогону — новый цикл историю НЕ обнуляет. Точное совпадение состава → уступает сиденье 3 (следующая по рангу незанятая рабочая семья пула); сдвинутый состав сверь снова, итерация ≤2; исчерпание → rotation_ok=relaxed+reason.
    - Precedence корректирующих правил: raw rank → anti-drift promotion 1.8 (≤1 буст/раунд) → anti-repeat shift (сиденье 3) → счётчик замен 1.4.
    - Недоступный слот пропускается (skip_reason + skip_source=matrix|runtime в манифесте). Пересев = добровольная смена роли/модели в ходе раунда — запрещён; аварийная замена упавшего — разрешена. Матрица доступности (ниже) помечает семьи без транспорта на хосте и «подтверждённую нежизнеспособность семья× роль×класс брифа» ЗАРАНЕЕ — не каскадом skip в рантайме; каждый живой сбой → предмарк в ту же правку.
1.3 Транспорт выбранной семьи: случайно из живых транспортов её слота (директива 08.10; model-invocation.md). Иерархия: размер 3 и рабочие процессы → уникальность семей → tier-major как порядок аварийного fallback внутри раунда.
1.4 Запуск, доступность и приёмка: три сиденья стартуют параллельно — наблюдаемый критерий: все три запущены до получения первого вердикта (PID/task-id и время старта — в манифест/processes.tsv); wall-clock раунда = максимум, не сумма. Доступность ленивая (preflight-ping пула запрещён). Первый токен ≤120 с — критерий только стримящих транспортов (curl/стрим-CLI); для Task — только полный вызов ≤600 с. БЮДЖЕТ РАУНДА ~15 мин — жёсткий потолок, отменяющий retry и замену: по исчерпании при <3 пришедших вердиктов общий вердикт панели НЕ выносится (NEEDS_RERUN либо эскалация владельцу), PASS запрещён; при трёх запущенных не закрывать
    по двум, пока третий в бюджете. Retry — 1, в пределах бюджета; далее skip. Падение слота (лимит, 429, пустой stdout, ActionRequiredError, таймаут, id отвергнут, лог не растёт) — перебор рабочих вариантов до набора 3 судей: (а) оставшиеся рабочие транспорты того же слота; (б) замена следующим рабочим кандидатом того же пула (tier 1 → tier 2 с приоритетом не занятых семейств); (в) tier 3 снят (Factory Droid снят 19.10.2026); (г) если из пула состав (3 судьи) не набирается — добор по п. 1.8: назначаются независимые сабпроцессы (отдельными внешними CLI-процессами через `launch_seat.py` с независимыми брифами) рабочих моделей и транспортов (из списков других ролей или уже подтверждённых рабочих моделей/транспортов пула, «⚠️ пул N/3»); нет ни одного рабочего транспорта — `QUORUM_UNAVAILABLE`. Fail-fast по reasoning (только стримящие транспорты): поток завершился (rc=0/[DONE]) при нулевом content → skip_reason=reasoning_budget немедленно; порог ≥90% max_tokens опционально; метрика — стрим-счётчик дельт оркестратора. Приёмка ответа: парсинг 6×VERDICT + ОБЩИЙ ВЕРДИКТ; внутри каждого критерия — подкатегории рубрики, по каждой — машиночитаемая SUB-строка «SUB <критерий>/<подкатегория>: PASS|FAIL|N/A — evidence (файл:строка/правило)» (N/A — с одной строкой
    почему); каждый FAIL — с issue-ID F-NNN и привязкой к файлу/строке/правилу; malformed := нет SUB-строки по любой подкатегории, FAIL без ID/привязки, сплошные N/A > 2/3 подкатегорий при нуле содержательных наблюдений → 1 retry с напоминанием формата (тот же слот, не сгорает) → замена по рангу (не четвёртый голос). Замена: таймаут → SIGTERM по своему PID из processes.tsv (Task — штатная отмена хоста; curl/CLI → 5 с → kill -KILL) → дождаться выхода → следующая по рангу рабочая модель/сабпроцесс; живых ≤3 всегда; счётчик: ≤1 замены в пользу семьи, сидевшей в
    предыдущем раунде; вторая не допускается (берётся кандидат другой семьи, иначе добор по 1.8). Потолок ≤6 вызовов судей на раунд — только лимит суммарных вызовов с учётом всех транспортных retry и аварийных замен после старта судей, включая замены из пула `default` и добор по п. 1.8; это НЕ разрешение на >3 судей или голосов и НЕ разрешение на >3 параллельных живых судей (одновременно ≤3; замена не добавляет голос и сиденье). НЕЗАВИСИМЫЙ ПЕРЕСЧЁТ (анти-самосертификация): детерминированно — судья с наименьшим рангом среди успешно стартовавших, не заменявшийся (отказ → следующий по рангу), ОБЯЗАН независимо пересчитать SEED и ranked_order по 1.1/1.2 и зафиксировать в своём вердикте; расхождение = блокер раунда.
1.5 Шляпы: hat_index = int(первые 8 hex SHA-256(seed_hex + '#hats'), 16) mod 6 — отдельный хеш. Таблица перестановок кортежа (Скептик, Реалист, Визионер), индексация с 0: 0:(С,Р,В) 1:(С,В,Р) 2:(Р,С,В) 3:(Р,В,С) 4:(В,С,Р) 5:(В,Р,С); назначение — по тройке сидений, отсортированной по pinned live ID (LC_ALL=C). Запрет повтора шляпы моделью из окна 2 раунда; сдвигается вся таблица (hat_index+k) mod 6; k — минимальное ≥1, устраняющее ВСЕ нарушения; нет валидного k∈1..5 → k=1, rotation_ok=relaxed; k и перечень нарушений — в манифест.
1.6 Манифест раунда (route-manifest.json; секреты ЗАПРЕЩЕНЫ — только slot_id/transport/пути): run_id, cycle, round, seed_input (байт-в-байт), seed_hex, artifact_sha256+путь, pool_setup, pool_source_rev (первые 8 hex SHA-256 этого файла на момент раунда), pool_ordered[], groups{native[],external[]}, ranked_order[], seats[{family, slot_id, transport, native|external, status, skip_reason, skip_source, retries, pid, killed_before_replace}], hats{}, hat_index(базовый), k, rotation_ok, fallbacks[], recheck{judge_family, seed_input_verbatim_ok, seed_hex_ok,
    ranked_order_ok, result}, family_usage_window (skip ≠ сидел; предмаркнутые исключены из анти-дрейфа), verdicts[], agreement, quorum_status (OK|NEEDS_RERUN|QUORUM_UNAVAILABLE), added_judges[] (requested→actual, роль-источник списка). ПРЕДрегистрация — постоянная норма: seed_input и ожидаемые составы публикуются в статусе цели ДО запуска судей. Манифест — на каждый начатый раунд, включая прерванные (status=aborted+причина), append-only; прикладывается к финальному статусу панели (вместе с составом и SEED). ГЕЙТ: старт судей запрещён, пока манифест не содержит seed_input, seed_hex, ranked_order[], seats[]; а для SDLC-панелей завершение раунда и сдача требуют верификации proof-of-launch через verify_panel_proof.py и генерации panel-proof.json со статусом PASS.
1.7 Операционка внешних вызовов: raw-захват тела + HTTP-код (без sed-фильтра в пайпе; pipefail); reasoning-слоты — max_tokens ≥32768; curl --connect-timeout 30 --max-time 600 --retry 0; raw-файлы mktemp вне Google Диска, очистка после раунда. СЕКРЕТЫ механизмом: заголовок авторизации только через curl --config <файл 0600, mktemp вне Диска> или stdin; раскрытие значения в argv запрещено; смоук «grep по ps -eo args и raw-логам пуст» — блокирующее предусловие первого
    внешнего вызова.
