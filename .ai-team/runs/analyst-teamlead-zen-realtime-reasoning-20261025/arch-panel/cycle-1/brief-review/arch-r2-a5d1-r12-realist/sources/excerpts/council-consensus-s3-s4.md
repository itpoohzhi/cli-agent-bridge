3. RECHECK. Механическая часть перепроверки FAIL (`universal-panel` ШАГ 1: grep «X уже есть»; веб-факт) оркестратор не применяет сам, а кладёт в пакет D1 строкой `RECHECK F-NNN: <команда → вывод>`.
4. Конфликты. Находки с взаимоисключающими фиксами (в том числе одного судьи) выявляют судьи (`CONFLICT`, §4), оркестратор их не ищет.
5. Цикл N≥2: красный verify-fixed по RW-NNN судья оформляет F-блоком (проектное решение: иначе у красного RW нет id для позиций; сам verify-fixed — council §3, «Diff-scope»); F-блок проходит те же раунды. Закрытые находки прошлых циклов в леджер не переносятся.
6. Новые находки в D-раундах: blocking — с меткой `[late-R2]` (счётчик `r2_late`, council §3; других имён не вводить — метка прежняя, хотя теперь охватывает любой D-раунд); non-blocking — без метки, в леджер (council §3). Получают следующий F-NNN (присваивает оркестратор механически) и участвуют в следующем раунде; находка из последнего D-раунда решается правилом потолка (§6). Судья называет новую находку собственным ярлыком (в тексте и в ссылках критериев); в пакете следующего раунда оркестратор публикует таблицу `СООТВЕТСТВИЕ ЯРЛЫКОВ: <ярлык> (<место>, <раунд>) → F-NNN`, а при расчёте §7 п.1 ссылки на ярлык раунда его появления сопоставляются с F-NNN по этой таблице; дальше судьи пользуются только F-NNN.

## 4. D-раунд: пакет, позиции, вопросы, анти-сикофантия

**Участники и состояние.** Судья и слот те же, что в R1 (фиксированы на проход, models.md §1.2 — один жребий в INIT/R1); шапочка хода — по циклической ротации Скептик → Реалист → Визионер → Скептик (`next(Скептик)=Реалист`, `next(Реалист)=Визионер`, `next(Визионер)=Скептик`) на КАЖДОМ D1..Dk, в каждом D представлены все три шапочки; смена шапочки = новый бриф места (§5), смена модели судьи аннулирует проход; судья stateless: «памяти» нет, всё приходит заново. Каждое место получает свой бриф `brief-v<K>.md` (§5).

**Пакет места** (всё — дословные копии; в порядке брифа):

1. Промпт шляпы + шапка тимлида + пакет приёмки + факт-карта + режим — как в R1 (council §1), с обёрткой D9.
2. `ВЕРДИКТ ТВОЕЙ РОЛИ В РАУНДЕ 1` и `АРГУМЕНТЫ ДРУГИХ ЭКСПЕРТОВ` — R1 трёх мест дословно; эти два блока есть в каждом D-раунде и в раунде согласия (JD-06 brief-review, `checklist-sources.md:246, 281`: R1 своей роли и двух других дословно, без комментариев оркестратора). Из шаблона R2 `universal-panel` (`references/run-steps.md`, «Шаблон промпта R2») берутся только эти два блока-контейнера с их заголовками; вводная «Раунд 2 дебатов…» (`run-steps.md:136`) и заключительные инструкции шаблона (`:151–155`: «Учти аргументы других экспертов… измени свою позицию», «При FAIL давай…», «ФОРМАТ ОТВЕТА (такой же как в Раунде 1)») в бриф не входят: они противоречат ПРАВИЛАМ ДЕБАТОВ (смена позиции только с ARG/NEW, формат ответа по раундам, §4). Приоритет при расхождении — ПРАВИЛА ДЕБАТОВ.
3. `ПРОТОКОЛ ДЕБАТОВ` — ответы всех мест всех прошлых раундов (содержимое `debate-transcript.md` на конец прошлого раунда); в D1 блока нет.
4. `СВОДНЫЙ ЛЕДЖЕР` — `consensus-ledger.md` целиком; плюс строки RECHECK (§3) и таблица `СООТВЕТСТВИЕ ЯРЛЫКОВ` (§3 п.6), если в прошлом раунде были новые находки.
5. Одна фактическая строка `РАУНД: D<k> из ≤<потолок>; последний: да|нет; место: <шляпа>` (как строка режима в R1; потолок 3 для всех пакетов, включая `fast`; «последний: да» — только при k=3, ранних выходов в v1 нет; шапочка — по ротации, прошлая шапочка указывается в строке), затем фактические строки, которые оркестратор получает из леджера механически: `ПОЗИЦИИ ТРЕБУЮТСЯ ПО: F-NNN, …; N=<число>` (чужие OPEN-находки и свои, оспоренные в прошлом раунде; в C1 вместо неё — `НЕСОГЛАСНЫЕ НАХОДКИ ЭТОГО МЕСТА: F-NNN, …; N=<число>`) и `ВОПРОСЫ К ТЕБЕ: Q-<M>-<место>-<n> — от <место> — <текст вопроса дословно>` (если есть); затем `ПРАВИЛА ДЕБАТОВ` — шаблон ниже дословно, без подстановок (вкладывается как артефакт-выдержка этого файла по D9, с sha256; не пересказ оркестратора).
6. Блок `ФОРМАТ ОТВЕТА (строго)` — единственный на весь бриф (в промпте шляпы или в `judge-prompt.md`, как в R1; JD-04), дословно по `universal-panel`; позиции и вопросы описаны отдельным блоком `ПРАВИЛА ДЕБАТОВ`, а не вторым блоком формата.

```text
ПРАВИЛА ДЕБАТОВ (номер раунда, признак «последний» и твоя шапочка хода — в строке РАУНД выше; судья и слот — по проходу, шапочка меняется по ротации Скептик → Реалист → Визионер → Скептик)
Всё выше — дословные копии, без комментариев оркестратора. Суди заново, чужой вердикт автоматически не подтверждай.
Цель — согласованное решение по КАЖДОЙ находке со status=OPEN, а не победа. В этом ходе ты надел следующую шапочку: пересмотри все открытые находки с новой позиции, сними необоснованные блокеры (с evidence) и предложи компромисс (AMEND).
1. По каждой находке из строки ПОЗИЦИИ ТРЕБУЮТСЯ ПО — ровно одна позиция (по своей неоспоренной находке — только если меняешь её); позиции по находкам вне строки не засчитываются и не ошибка:
   AGREE F-NNN rev=<r> — проверил: <file:line> — что увидел сам
   DISPUTE F-NNN — класс: invalid | duplicate_of:F-MMM | out_of_scope | foreign_key — контр-evidence: <file:line или цитата правила> — почему неверно
   AMEND F-NNN — priority=<blocking|non-blocking>; locations=<file:line,…>; fix=<…> — причина: <file:line или цитата правила>
   WITHDRAW F-NNN — только своя находка — ARG или NEW (как в п.2); проверил: <file:line>
   INCONCLUSIVE F-NNN — что нужно для проверки (не голос)
2. Первая твоя позиция по находке — не смена, ARG/NEW для неё не нужен (в том числе если ты заменил выбывшего судью по транспортной лестнице; смена шапочки по ротации сменой позиции не считается, но и не освобождает от ARG/NEW при изменении твоей прежней позиции: прежние позиции — твоя история в леджере). Смена своей прошлой позиции (включая AMEND/WITHDRAW своей находки) — только с `ARG: <место/раунд «дословная цитата коллеги»>` (довод коллеги) либо `NEW: <file:line>` (твоя новая проверка, которой не было в прошлых репликах) и с твоей собственной проверкой <file:line>. Смена без ARG/NEW — malformed. Повторить прежнюю позицию без нового довода можно.
3. Вопросы коллеге — не более 3 за раунд (в последнем раунде вопросов нет), адресно: `Q→<место>: F-NNN <file:line> — вопрос` (id вопросу присваивает оркестратор, ты его не пишешь). На вопросы из строки ВОПРОСЫ К ТЕБЕ: `A←Q-<id из строки> — ответ + <file:line>`; ответ без проверяемой ссылки не считается ответом.
4. Взаимоисключающие фиксы двух находок: `CONFLICT F-a↔F-b — почему`.
5. Новая находка — полный F-блок: blocking — с меткой [late-R2], non-blocking — без метки, в леджер; позиции по OPEN-находкам она не заменяет. Найденная в последнем раунде решается правилом потолка без обсуждения.
6. Ответ: строки позиций/вопросов/ответов, затем ФОРМАТ ОТВЕТА (6 критериев; при FAIL — ссылки на F-NNN; INCONCLUSIVE критерия — что нужно для проверки). SUB-строки и COVERAGE в D-раунде не нужны (правило шапки о них относится к R1); `FINDINGS_COMPLETE: <N>` — только если в ответе есть новые F-блоки (N — их число). Последние строки: `POSITIONS: <n>/<N>` (n — число твоих позиций по находкам из строки ПОЗИЦИИ ТРЕБУЮТСЯ ПО, N — их число из строки) и `ANSWERS: <a>/<A>` (A — число вопросов в строке ВОПРОСЫ К ТЕБЕ), при новых F-блоках — ещё `FINDINGS_COMPLETE`.
```
