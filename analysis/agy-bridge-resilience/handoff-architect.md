# Handoff-пакет Системного Аналитика для Архитектора

## 1. Контекст и архитектурные драйверы (Architecture Drivers)
1. **DRV-01 (Защита от зависания):** Мост DSH `agy-bridge` не должен удерживать соединение 1800 секунд в состоянии «мертвого зависания», когда дочерние процессы не производят CPU-работы и не порождают событий [F-01, F-02].
2. **DRV-02 (Адаптивный Watchdog):** В мост должен быть интегрирован двухконтурный сторожевой таймер активности по образцу `core/watchdog.py` [F-08]: контур активности `IDLE_TIMEOUT_S = 300.0` с (сброс по протокольным событиям или дельте CPU > 0) и предохранительный потолок `SAFETY_CAP_S = 1800.0` с.
3. **DRV-03 (Корректное завершение деревьев процессов):** При наступлении таймаута мост обязан уничтожать всю группу процессов (`kill -9 -<pgid>`), предотвращая утечку зомби-процессов браузера/инструментов [F-09].
4. **DRV-04 (Единое версионирование и поставка):** Мост `agy-bridge` должен войти в репозиторий `cli-agent-bridge` в каталог `bridges/agy-bridge` (по аналогии с `bridges/muse-bridge`) [F-10, F-11], сопровождаться юнит-тестами, проходить CI/CD проверки, вливаться в `dev` и `main` и управляться `launchd` службой `com.user.dsh-agy-bridge`.
5. **DRV-05 (Hotfix клиентского скрипта):** В `fetch_via_playwright.py` должен быть внедрен детерминированный таймаут `asyncio.wait_for(..., timeout=60)` и `AbortSignal.timeout(15000)` во внутреннем `fetch`, исключающий подвисание на сбойных SSL-эндпоинтах [F-05, F-06, F-07].

## 2. Границы As-Is и Проблемные зоны
- **As-Is `~/.dsh/bridges/agy-bridge/server.py`:**
  - Монолит без git-трекинга.
  - Нет контроля активности процессов (только слепой `time.monotonic() > deadline` на 1800с).
  - При `tools` в запросе текст модели удерживается до выхода процесса; если фоновый процесс агента висит, клиент 30 минут видит спиннер, после чего получает ошибку 500 / timeout.
  - При таймауте не все дочерние процессы (запущенные через sh/uv) погибают, оставаясь висеть в памяти.
- **As-Is `scripts/fetch_via_playwright.py`:**
  - Отсутствие внешнего таймаута на обработку отдельного источника.
  - В JS-парсере `EXTRACT_JS` нативный браузерный `fetch(url)` вызывается без `signal`, что подвешивает вкладку Chromium при разрыве TCP/TLS сокета.

## 3. Маппинг на Architecture Packet
- **Evidence:** `[F-01]..[F-11]` из `evidence-ledger.md`.
- **Blocking open questions:** Отсутствуют (все вопросы классифицированы как МОЖНО ПРОДОЛЖИТЬ).
- **Assumptions:** `OPEN-01`, `OPEN-02`, `OPEN-03` из `open-questions.md`.
- **Boundaries & Contracts:**
  - API эндпоинт: `POST /v1/chat/completions` (OpenAI format, SSE stream).
  - Порт: `127.0.0.1:9887` (служба `com.user.dsh-agy-bridge`).
  - Egress: канонический лончер `~/.config/agy-launch/agy-cli.sh`.
  - Модель каталога: `fleet.json` (версия схемы 2/3).
- **Quality Scenarios (NFR):**
  - **NFR-RES-01:** Зависший дочерний процесс прерывается не позднее чем через 300 секунд неактивности с возвратом структурированной ошибки клиенту, порт освобождается.
  - **NFR-RES-02:** Утечка PID исключена — все потомки группы процесса гасятся через SIGKILL группы.
  - **NFR-RES-03:** 100% покрытие новыми юнит-тестами для watchdog-логики `agy-bridge`.

## 4. Рекомендации Архитектору
1. Оформить `bridges/agy-bridge` как модуль в репозитории `cli-agent-bridge`.
2. Использовать `core/watchdog.py` (`ProcessWatchdog`) для мониторинга `pgid` дочернего процесса `agy`.
3. Добавить в `_execute` проверку `watchdog.is_idle(IDLE_TIMEOUT_S)` и возврат ошибки `state("idle_timeout", 124, "process tree inactive for 300s")`.
4. Подготовить спецификацию тестов (`tests/test_agy_bridge_resilience.py`).
5. Зафиксировать изменения в ADR-0007.
