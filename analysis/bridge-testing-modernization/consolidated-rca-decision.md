# Консолидированное RCA и Решение аналитической панели

## Причинная модель (RCA)

1. **Почему склеивались строки («данных.Проверяю вывод», «и провИщу»)?**
   - **Причина:** `_ContentArbiter` и `Run.offer_content` добавляли новые фрагменты шагов в `self.chunks` без проверки границ строк. При переходе от завершённого шага к новому шагу транскрипта отсутствовала вставка переноса строки `\n\n`.
   - **Почему не ловили тестами:** Тесты оперировали изолированными парами строк `alpha` и `beta` без валидации структуры Markdown-потока.

2. **Почему циклически дублировались префиксы («[гейт оркестрации: активен...»)?**
   - **Причина:** В методе `_ContentArbiter._scan` условие `texts[pos].startswith(text)` ошибочно сопоставляло короткий префикс нового шага (например, символ `[` или `[статус: `) со старым длинным текстом уже завершённого шага. При дальнейшем сравнении в `_advance` кандидат не являлся префиксом старого, фиксировался `content-divergence`, шаг замораживался, а арбитр на следующем тике создавал новый шаг и с нуля переэмитил весь префикс.
   - **Почему не ловили тестами:** Тест сопоставлял только случай точного префикса с индексом, но не моделировал ситуацию, когда новый шаг начинается с совпадающей преамбулы.

3. **Почему схлопывался аккордеон мышления `<Think>` в UI DeepSeek Harness?**
   - **Причина:** В `_TranscriptTail._emit_record` преамбула шага с вызовом инструмента передавалась в `emit_content` -> `choices[0].delta.content`. По протоколу UI DeepSeek Harness получение первого же `delta.content` закрывает фазу Thinking (`<Think>`), и все последующие размышления из транскрипта либо блокируются, либо аппендятся в закрытый верхний аккордеон, а промежуточные сервисные логи засоряют окно сообщения.
   - **Почему не ловили тестами:** Тесты стриминга проверяли только факт отдачи любого контента, не валидируя семантическую изоляцию `reasoning_content` vs `content`.

## Консолидированное решение и целевая архитектура тестирования

Панель аналитиков единогласно утверждает **Вариант V3** (трехуровневая архитектура тестирования + обновление регламентов):

1. **L1 (Unit / Arbiter Core):**
   - Исправление `_scan`: сопоставление кандидата только при точном равенстве `text == candidate` либо истинном расширении `text.startswith(candidate)`.
   - Исправление `_advance` / `offer_content`: гарантия разделителя `\n\n` на границе шагов при отсутствии переводов строк.
   - Нормализация и исправление `_parse_runtime_flags` (поддержка alias `AGY_GRACEFUL_TIMEOUT_FINISH_REASON`, валидация fallback `stop`).

2. **L2 (Synthetic E2E & Protocol Verification):**
   - Разработка нового сьюта `tests/test_stream_formatting_and_subagents.py`:
     - Тест разделения шагов Markdown `\n\n` (отсутствие склеивания слов).
     - Тест исключения лавины префиксов при многократной смене шагов с общими преамбулами.
     - Тест изоляции `reasoning_content` при вызовах инструментов (`tool_calls`).
     - Тест моделирования жизненного цикла агента со скиллами оркестрации (`cel`, сабагенты `Task`/`invoke_subagent`).

3. **L3 (Universal Smoke Runner):**
   - Разработка автономного инструмента `scripts/smoke_models.py`, проверяющего модели и транспорты из `~/Мой диск/Context/models.md` через эндпоинты моста, с маскированием токенов и замером TTFT.

4. **Регламент в AGENTS.md:**
   - Закрепление обязательных правил тестирования моста: запрет сдачи без L1/L2 проверок стриминга и изоляции reasoning.

Уровень уверенности панели: **ВЫСОКИЙ (100% консенсус 3 шляп)**.
Рекомендуемый следующий шаг: передача требований в архитектуру (`handoff-architect.md`) и переход к реализации.
