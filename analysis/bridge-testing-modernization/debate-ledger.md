# Журнал дебатов аналитической панели (Debate Ledger)

Дебаты 3 шляп (Причинный аналитик / Белая, Скептик / Чёрная, Аналитик вариантов / Зелёная).

---

### Дискуссия 1: Включение живых вызовов моделей в общий набор `pytest tests/`

- **Позиция Зелёной шляпы:** Включить смоук-тесты моделей прямо в сьют `pytest tests/`, чтобы ни один коммит не проходил без проверки всех моделей.
- **Возражение Чёрной шляпы ([B-02]):** Это приведёт к постоянным падениям CI (flakiness) из-за сетевых сбоев, исчерпания квот API или недоступности отдельных провайдеров. Быстрый цикл TDD (<10 сек) превратится в 15-минутное ожидание.
- **Аргумент Белой шляпы ([W-06]):** В `models.md` перечислено более 15 моделей, часть из которых периодически находится в статусе `TEMP OFF` или квотирована. Жёсткое падение pytest на внешних моделях заблокирует локальную работу.
- **Консенсус (Решение):** Разделение на уровни. В `pytest tests/` входят **только детерминированные синтетические тесты** L1/L2 с локальными mock-серверами и симулятором транскриптов. Смоук-тестирование реальных моделей выносится в автономный CLI-раннер `scripts/smoke_models.py`, запускаемый вручную или на шаге предварительной приёмки (pre-flight).

### Дискуссия 2: Способ проверки изоляции `reasoning_content`

- **Позиция Чёрной шляпы ([B-01]):** Если мы жестко перенаправим все преамбулы в `reasoning_content`, клиенты, не поддерживающие поле `reasoning_content` (обычный `curl`, OpenAI SDK v1 без extended thinking), не увидят текста статусов вовсе.
- **Позиция Зелёной шляпы ([G-02]):** В OpenAI Chat Completions API поле `reasoning_content` поддерживается всеми клиентами DeepSeek / vLLM. Однако для универсальности моста перенаправление преамбул инструментов должно быть управляемым через конфигурацию `isolate_tool_preambles_to_reasoning` (по умолчанию `True` для совместимости с Harness UI, но с возможностью отключения через env/dynamic config).
- **Позиция Белой шляпы ([W-04]):** Факт: именно наличие текста в `choices[0].delta.content` при наличии `tool_calls` вызывает досрочное закрытие аккордеона `<Think>` в DeepSeek Harness. Изоляция преамбул в `reasoning_content` полностью восстанавливает естественное поведение UI.
- **Консенсус (Решение):** Реализовать управляемую изоляцию: при наличии `tool_calls` преамбула уходит в `reasoning_content`, а `content` остаётся пустым до получения итогового ответа или реконсиляции. Тесты обязаны проверять оба сценария (с включенным и выключенным флагом).

### Дискуссия 3: Проверка форматирования Markdown и разделителей `\n\n`

- **Позиция Чёрной шляпы ([B-03]):** Если просто безусловно добавлять `\n\n` перед каждым новым куском текста, агент начнёт рвать предложения посреди фразы.
- **Позиция Белой шляпы ([W-02]):** Склеивание строк происходило именно на стыке разных шагов (`step_index` в транскрипте). Токены одного и того же шага приходят с непрерывным префиксом.
- **Консенсус (Решение):** Разделитель `\n\n` должен добавляться только:
  1) при переходе к новому шагу (`step_index` изменился);
  2) при смене источника эмиссии (например, переход от `stdout` к `transcript` или к `result`);
  3) и строго при условии, что уже выданный буфер не оканчивается на `\n` или `\n\n`.
  Тестовый инспектор обязан проверять отсутствие склейки строк и отсутствие лишних разрывов.
