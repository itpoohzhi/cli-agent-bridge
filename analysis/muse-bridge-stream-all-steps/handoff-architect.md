# handoff-architect: Сквозной live-стриминг всех шагов рассуждений и действий модели

## 1. Входные требования и драйверы архитектуры
- REQ-001: Непрерывная монотонная трансляция всех шагов размышлений модели (summary.0, summary.1, ..., summary.N) в SSE поток через delta.reasoning_content в реальном времени. Снятие искусственной заморозки live-потока [F-01, F-02, F-03, F-04].
- REQ-002: Отображение прогресса выполнения инструментов (toolCall, bash, readFile, writeToFile) в UI DeepSeek Harness в реальном времени во избежание «пустого экрана» при длительных ходах [F-05, F-08].
- REQ-003: Сохранение и опережающий сброс накопленного буфера reasoning_content в SSE поток перед закрытием соединения при возникновении ошибок или истечении таймаута [F-06, F-07].
- REQ-004: Полная обратная совместимость с нестриминговым режимом (stream=false) и существующими тестами моста.

## 2. As-is границы и выявленные ограничения
- Входной контракт: HTTP POST /v1/chat/completions (OpenAI-совместимый эндпоинт).
- Транспорт CLI: фоновый процесс Meta CLI serve, управляемый через JSON-RPC over stdio [F-01].
- Ограничение текущей реализации: флаг _live_frozen взводится в True при первом завершении reasoning item или при idx > 0, блокируя отправку всех последующих дельт рассуждений [F-02, F-03].
- Ограничение буферизации: метод _send_sse накапливает summaries и выдаёт их целиком только в конце успешного хода [F-04].
- Ограничение обработки ошибок: метод _send(502, ...) сразу отправляет кадр SSE error и DONE, теряя промежуточные рассуждения [F-06].
